# 净化原则：保取内容，灭报信

_Status: accepted_

原版 kejilion.sh 的对外请求分两类：**取内容**（下载安装包、测速节点等用户明确要用的东西）和**报信**（把用户是谁、机器什么配置发给原作者或第三方）。红线是“不能把我的信息发给别人”，同时安装、测速等正常功能必须原样保留。我们决定：取内容一律保留（顺路抹掉请求里能识别身份的成分），报信一律删除或替换成本地等价物。这条原则对本仓库后续所有修改生效，不许再把报信加回来。

## Considered Options

- **彻底断网**：所有对外请求全删。否决——直接废掉装 Docker、测速等一大片功能，违背“正常功能不用管”的前提。
- **逐功能点人工判断**：每个请求单独决定。否决——成本高、口径会漂移，且没有可复现的验收标准。
- **保取内容、灭报信（选定）**：口径一条线，还能写成命令行可复现的清点检查，每次改动都能自动验证。

## Consequences

- 净化版**仍然有对外请求**（GitHub 镜像、下载源、测速节点）。看到网络请求不等于报信，别当 bug 再“修”回去。
- 判定口径来自术语表（GLOSSARY.md 的“报信”/“取内容”），清点脚本是这条原则的守门人。验收只包含可自动复查的部分（报信清零 + VPS 冒烟测试）；最终人工过目由仓库主人自己做，不占代理的验收范围。
